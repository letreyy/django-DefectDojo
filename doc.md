# Full DevSecOps CI/CD Pipeline

Этот репозиторий содержит полную реализацию CI/CD пайплайна с интеграцией DevSecOps практик: статический анализ (SAST), анализ зависимостей (Security Checks), динамическое тестирование (DAST), Security Gateway и автоматический деплой. Все отчеты уязвимостей автоматически загружаются в DefectDojo.

## **Структура пайплайна**

Весь пайплайн запускается из .github/workflows/full-pipeline.yml.

Пайплайн состоит из 5 основных этапов:

1. **SAST (Static Application Security Testing)**
   - **Инструмент:** [Bandit](https://bandit.readthedocs.io/).
   - **Описание:** Сканирует исходный код Python на наличие уязвимостей.
   - **Выбор:** Bandit прост в интеграции и хорошо работает для Python.
   - **Результат:** Отчет в формате JSON отправляется в DefectDojo (engagement 1).

2. **Security Checks (Зависимости и контейнеры)**
   - **Инструмент:** [Trivy](https://aquasecurity.github.io/trivy/).
   - **Описание:** Сканирует файловую систему и Docker-образы на наличие уязвимостей.
   - **Выбор:** Trivy поддерживает файловые и контейнерные сканы, быстро интегрируется.
   - **Результат:** Отчет в формате JSON загружается в DefectDojo (engagement 2).

3. **DAST (Dynamic Application Security Testing)**
   - **Инструмент:** [OWASP ZAP](https://owasp.org/www-project-zap/).
   - **Описание:** Выполняет динамическое тестирование веб-приложения.
   - **Выбор:** ZAP является индустриальным стандартом для DAST.
   - **Результат:** HTML отчет загружается в DefectDojo (engagement 3).

4. **Security Gateway**
   - **Описание:** Проверяет отчеты всех сканеров на наличие **CRITICAL** уязвимостей.
   - **Механизм:** Использует `jq` для подсчета уязвимостей в отчетах Trivy и Bandit. Также проверяет DAST-результаты.
   - **Поведение:** Если найдены критические уязвимости, деплой блокируется.

5. **Deploy**
   - **Описание:** Деплой обновленного приложения на VPS.
   - **Механизм:** Через SSH подключение с использованием приватного ключа (`SSH_KEY`).

---

## **Архитектура**

```text
Push -> GitHub Actions -> SAST -> Security Checks -> DAST -> Gateway -> Deploy
```

Все шаги пайплайна связаны через директиву `needs:` в GitHub Actions, что гарантирует последовательное выполнение.

---

## **GitHub Secrets**

Для работы пайплайна необходимо настроить секреты:
- **DD_TOKEN** – API Token для DefectDojo.
- **SSH_KEY** – приватный ключ для деплоя.
- **SSH_USER** – имя пользователя на сервере.
- **SSH_HOST** – адрес сервера (например, `185.178.44.115`).

---

## **Зоны роста**

- **Интеграция с Snyk или DependencyTrack** для более глубокого анализа зависимостей.
- **Добавление unit-тестов и coverage** перед SAST.
- **Добавление автоматических pull-request комментариев** по найденным уязвимостям.
- **Использование ZAP Full Scan** для более агрессивного тестирования.
- **Параллелизация шагов** (например, SAST и Security Checks можно запускать одновременно).

---


## **Заключение**

Созданный пайплайн полностью автоматизирует процесс CI/CD с интеграцией DevSecOps и обеспечивает контроль безопасности на всех этапах разработки. Он может быть расширен новыми сканерами и улучшен с точки зрения автоматизации анализа и отчетности.
